三种主运行路线，先选一种

纸面路线：HTML / SVG / CSS。 文字、照片、折页和少量物件为主，优先保留阅读体验。遮罩与裁切已经能提供非矩形视觉表达。S07

插画舞台路线：PixiJS。 透明图层、物件和局部特效为主。我们的首作默认候选是“Vite + TypeScript + PixiJS（先 WebGL）+ GSAP + 可选 Howler.js”，正文与控制使用 HTML。这里是组合建议，不是唯一正确技术栈。S08 S19 S22 S31

立体物件路线：Three.js。 只有当背面、转动、开合或真实空间是表达的一部分时，才承担 3D 资产与材质的额外工作。可以用 Blender 制作、glTF 交付；也可以制作端用 3D，运行端只播放预渲染结果。S14 S15

一件作品通常不需要同时安装 PixiJS、Three.js、Rive、XState 和全部特效插件。先复用一种运行骨架，再为少数不可替代的效果加能力。

依据与边界

这一项是本项目的制作方法建议，不是某个模型已经保证的能力。沿用备忘录“经历决定形式”“技术服务于感受”的原则。

实现思路 · 项目建议

先写一个核心感受，再确定视角、光源、色板、材质和文字位置；用一张完成度高的目标画面作为参照。

按将来的动作制作资产：会移动的物件、物件阴影、被遮挡的背景分别保留；正文、姓名和日期独立排版。保留横屏与竖屏的构图草案。

把候选素材放进同一画面检查光向、比例、颗粒和边缘，不以单张生成图的惊艳程度决定是否采用。

输入与产物

输入：经过确认的经历、照片、文字。输出：目标画面、风格说明、分层源文件与素材清单。

容易踩的坑

AI 图像生成并不会自动保证多素材一致性。透明素材须检查真正的 Alpha 通道，不能把棋盘格背景当成透明。

更简单的替代

缩小到一个主场景、少量物件；不为了画面复杂而增加第二种画风。

最小验证实验

把所有动态关掉，检查桌面、手机两种画幅中的视觉焦点、文字可读性和素材接缝。

想要的体验

从真实照片或插画中取出一张票、一件礼物或一片前景，使它可以独立响应操作。

依据与边界

SAM 3 支持文本及视觉提示下的图像／视频分割；官方仓库还记录了 SAM 3.1 多物体跟踪更新。这里需要的是分割输出，不是重新生成整张图。 S03

实现思路 · 项目建议

给出文字、点或框提示，取得候选 mask，先确认选中的确实是目标。

将 mask 作为初始透明度区域，再清理边缘、去掉原背景色污染；软毛、烟雾和玻璃应单独处理。

导出透明图，并人工设置便于触摸的命中区域。命中区域可以略宽于视觉轮廓，不必逐像素点击。

输入与产物

输入：原图与目标提示。输出：mask、透明前景、简化的交互轮廓。

容易踩的坑

分割不等于精细 Alpha matting，也不补出原本不可见的部分。不要把 3.1 的跟踪改进理解为静态抠图必然更漂亮。官方运行前提和权重访问要求须检查。

更简单的替代

用手工路径／蒙版处理最关键的一两件物品；小作品不必自动化全部资产。

最小验证实验

把前景分别放到浅色、深色和高对比背景上，检查白边、残影与误删；再测试手指能否稳定选中。

依据与边界

实现思路 · 项目建议

实现思路 · 项目建议

输入与产物

容易踩的坑

最小验证实验

在四个方向移动视角，检查人脸／文字是否变形、边缘是否撕裂；减少动态模式下应可完整静态观看。

依据与边界

实现思路 · 项目建议

输入与产物

最小工程组织

下面是建议性的组织方式，不是需要预先实现的平台。核心分界是：制作端负责生成与审核，运行端负责确定性地呈现与交互。

A. 制作端：从素材到可控资产

经历与素材 → 目标画面 → 分层／补全／建模 → 人工检查 → 面向设备的优化 → 交付资产

尽量把 AI 放在这里。一个候选资产经过挑选、修改和确认后，再进入作品。接收者打开时不必等待模型，也不必承受临场生成带来的内容漂移。对制作成本的判断应记录总重试与人工修整，不只记录一次推理时间。

B. 运行端：三层逻辑即可起步

内容与资产层： 真实正文、图片、声音、布局和来源引用。
交互状态层： 当前场景、允许动作、事件与完成条件。
表现层： 画面、声音、时间线与阅读界面。

这是一种职责划分，不要求三个大框架。不要把故事逻辑写进每一张图片的动画回调里，也不要让切换画质重置故事进度。

性能数字如何记录

不要事先写“所有手机 60 FPS”或“支持十万粒子”。若目标为 60 FPS，一帧总时间约为 16.7 ms；30 FPS 约为 33.3 ms，这是时间预算换算，不是本项目已达到的指标。

记录目标设备、分辨率／画布像素倍率、运行场景与持续时间，观察最差时刻而不只看平均值。纹理与绘制缓冲区的管理依据见官方实践。S28

何时不用一项技术

当它没有带来新的表达、只在开发机成立、需要反复修理不可控素材，或会迫使接收者学习操作时，退回简单路线不是失败。把原因记进实验卡，技术库才会逐渐包含你们自己的判断，而不只是外部工具说明。
