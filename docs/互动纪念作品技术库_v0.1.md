# 互动纪念作品技术库

**v0.1 · 2026-09-06**  
体验索引 · 技术卡片 · 组合配方 · 实验记录

> 复用制作能力，不复用别人的故事。

这份库服务于一种小而完整的作品：把一段真实经历，变成可以打开、参与、赠送和收藏的体验。它不是通用前端百科，也不是“把全部新技术装进去”的任务清单。

**内容依据。** 作品原则来自用户提供的《思考备忘录｜把共同经历变成可探索的作品》：经历决定形式，交互参与叙事，技术不是主角，先完成一件作品再考虑平台。原文相关位置为第 11–31 行。[M01]

**阅读边界。** 技术能力依据本轮公开官方文档、模型卡、官方仓库及作者项目页核验；“补充调研”标注了上一轮讨论之外新增的具体工具或路线。每张卡片的实现流程、取舍和验收方法是面向本项目的设计建议，不是官方承诺。未实际运行这些模型或特效组合，也未测量目标手机的性能。此库是研究与实现路线库，不冒充已完成的代码组件库。

“默认优先／按需采用／先做小样／实验储备”是**本项目的使用建议**，不是客观成熟度评级；软件自身的实验性状态另行注明。核验日期不意味着收录了截至该日的全部前沿进展。

## 01 · 从想要的体验反查技术

先写下“接收者做什么、看见什么变化、为什么这件事与这段经历有关”，再选技术。下面的路线只是入口，不冻结作品形式。

| 想要的体验 | 首先看哪些卡片 | 最低成本可行形式 | 什么时候再升级 |
|---|---|---|---|
| 一封会展开的信、一张有纸感的桌面 | [T01](#T01)、[T07](#T07)、[T15](#T15) | HTML / SVG / CSS | 物件、层次和局部变形变多时，再用 PixiJS |
| 手绘地图、可探索房间、窗边桌面 | [T03](#T03)、[T05](#T05)、[T08](#T08) | 多层透明图与少量命中区域 | 真正需要物件背面或空间转动时再做 3D |
| 一张照片有轻微空间感 | [T04](#T04)、[T05](#T05) | 人工分层视差 | 自动深度能减少制作工作且没有明显伪影时再采用 |
| 风吹窗帘、纸张弯动、丝带展开 | [T09](#T09) | 旋转或稀疏网格变形 | 需要真实折叠／背面时再转向 3D |
| 雨玻璃、水面、热气和微光 | [T10](#T10)、[T14](#T14) | 局部滤镜或循环视频 | 交互必须连续改变画面时再写定制 Shader |
| 散落碎片拼回照片或一句话 | [T11](#T11)、[T15](#T15) | 少量碎片＋清晰终图 | 测出对象数量瓶颈后再评估 GPU 计算 |
| 可以翻转的纪念品、会打开的礼盒 | [T06](#T06)、[T12](#T12) | 固定机位 3D／预渲染多视角 | 自由机位对表达有价值时才扩大范围 |
| 在真实空间的一角停留 | [T13](#T13) | 限定视角图片／视频 | 实时空间感确实不可替代时再采用 Splat |
| 声音随操作和场景变化 | [T18](#T18) | 少量分组音轨 | 需要空间定位或复杂处理时再用更细的音频节点 |
| 一件会响应的小插画／图形角色 | [T19](#T19) | SVG ＋简单状态 | 动画状态和设计迭代较多时采用 Rive |
| 手机顺畅、静音可用、还能收藏 | [T20](#T20)–[T23](#T23) | 响应式场景＋替代阅读路径 | 不把这些留到成品以后补救 |

### 三种主运行路线，先选一种

**纸面路线：HTML / SVG / CSS。** 文字、照片、折页和少量物件为主，优先保留阅读体验。遮罩与裁切已经能提供非矩形视觉表达。[S07]

**插画舞台路线：PixiJS。** 透明图层、物件和局部特效为主。我们的首作默认候选是“Vite + TypeScript + PixiJS（先 WebGL）+ GSAP + 可选 Howler.js”，正文与控制使用 HTML。这里是组合建议，不是唯一正确技术栈。[S08] [S19] [S22] [S31]

**立体物件路线：Three.js。** 只有当背面、转动、开合或真实空间是表达的一部分时，才承担 3D 资产与材质的额外工作。可以用 Blender 制作、glTF 交付；也可以制作端用 3D，运行端只播放预渲染结果。[S14] [S15]

一件作品通常不需要同时安装 PixiJS、Three.js、Rive、XState 和全部特效插件。**先复用一种运行骨架，再为少数不可替代的效果加能力。**

### 五种资产，不要混为一谈

| 产物 | 回答的问题 | 不能自动替你完成 |
|---|---|---|
| 分割 mask | 哪些像素属于目标物体？ | 精细透明度、被遮挡区域补全、物体动作 |
| RGBA 图层 | 哪些画面内容可以分开合成？ | 故事结构、正确轴心、命中区域与状态 |
| 深度图 | 各位置的深度如何估计？ | 被遮挡面的真实内容、可自由漫游的完整场景 |
| Mesh ＋材质 | 几何表面及其材质如何表示？ | 自动正确的部件、骨骼、交互逻辑和轻量化 |
| Gaussian Splat | 如何渲染一种空间外观表示？ | 普通网格编辑、碰撞几何与逐件开合机制 |

上表将工具输出与本项目还需要的工作区分开；对应技术依据见 T02–T06、T12–T13。[S03] [S01] [S04] [S38] [S17]

<a id="group-1"></a>
### 资产制作

先把画面变成可控制、可审核的素材。AI 输出只是制作链中的一站。

<a id="T01"></a>
### T01 · 先建立可控制的美术资产

**默认优先** · 制作端 · 实现投入：中 · 前文整理

关键词：美术 / 构图 / 素材 / 风格统一

**想要的体验。** 暂停全部动画后，画面仍然值得看；每件物品看起来属于同一个世界。

**依据与边界。** 这一项是本项目的制作方法建议，不是某个模型已经保证的能力。沿用备忘录“经历决定形式”“技术服务于感受”的原则。

**实现思路（项目建议）。** 先写一个核心感受，再确定视角、光源、色板、材质和文字位置；用一张完成度高的目标画面作为参照。

按将来的动作制作资产：会移动的物件、物件阴影、被遮挡的背景分别保留；正文、姓名和日期独立排版。保留横屏与竖屏的构图草案。

把候选素材放进同一画面检查光向、比例、颗粒和边缘，不以单张生成图的惊艳程度决定是否采用。

**输入与产物。** 输入：经过确认的经历、照片、文字。输出：目标画面、风格说明、分层源文件与素材清单。

**容易踩的坑。** AI 图像生成并不会自动保证多素材一致性。透明素材须检查真正的 Alpha 通道，不能把棋盘格背景当成透明。

**更简单的替代。** 缩小到一个主场景、少量物件；不为了画面复杂而增加第二种画风。

**最小验证实验。** 把所有动态关掉，检查桌面、手机两种画幅中的视觉焦点、文字可读性和素材接缝。

**资料入口：** 用户备忘录 [M01]；本条为项目制作方法建议。

<a id="T02"></a>
### T02 · 语义分割与抠图：把指定物件取出来

**先做小样** · 制作端 · 实现投入：中 · 补充调研

关键词：SAM 3 / SAM 3.1 / 分割 / mask / 抠图

**想要的体验。** 从真实照片或插画中取出一张票、一件礼物或一片前景，使它可以独立响应操作。

**依据与边界。** SAM 3 支持文本及视觉提示下的图像／视频分割；官方仓库还记录了 SAM 3.1 多物体跟踪更新。这里需要的是分割输出，不是重新生成整张图。 [S03][S03]

**实现思路（项目建议）。** 给出文字、点或框提示，取得候选 mask，先确认选中的确实是目标。

将 mask 作为初始透明度区域，再清理边缘、去掉原背景色污染；软毛、烟雾和玻璃应单独处理。

导出透明图，并人工设置便于触摸的命中区域。命中区域可以略宽于视觉轮廓，不必逐像素点击。

**输入与产物。** 输入：原图与目标提示。输出：mask、透明前景、简化的交互轮廓。

**容易踩的坑。** 分割不等于精细 Alpha matting，也不补出原本不可见的部分。不要把 3.1 的跟踪改进理解为静态抠图必然更漂亮。官方运行前提和权重访问要求须检查。

**更简单的替代。** 用手工路径／蒙版处理最关键的一两件物品；小作品不必自动化全部资产。

**最小验证实验。** 把前景分别放到浅色、深色和高对比背景上，检查白边、残影与误删；再测试手指能否稳定选中。

**资料入口：** [S03][S03]

<a id="T03"></a>
### T03 · 生成式图层分解：一张图变成多层 RGBA

**先做小样** · 制作端 · 实现投入：中 · 前文整理

关键词：Qwen-Image-Layered / RGBA / 自动分层 / AI

**想要的体验。** 尽量保留一张画面原有的构图，把背景、物件和装饰变成可单独移动的层。

**依据与边界。** Qwen-Image-Layered 的核心任务是从一张图分解出多张 RGBA 图层。官方明确说：提示词不是精确指定每层内容的控制器；发布权重也不应当成成熟的文生多层图工具。 [S01][S01] [S02][S02]

**实现思路（项目建议）。** 先拿一张真实候选画面做分解，再将结果重新合成，与原图对照。

逐层检查角色／照片身份、文字、阴影、透明边缘和遮挡是否被改写；再按交互需要合并或细分层。

重要物件单独修整。记录采用的模型、检查点和参数，保留原图与未改动的事实素材。

**输入与产物。** 输入：RGB／RGBA 参考图。输出：经过审核的 RGBA 层组，以及各层用途。

**容易踩的坑。** 生成式分解不保证像素级复原，也不自动给出正确的交互结构。官方示例推荐分辨率不等于你的全屏成品质保。

**更简单的替代。** 保留原始背景，只有一两个前景用人工抠图或单独绘制；不要为全自动分层牺牲事实与画质。

**最小验证实验。** 先测重新合成是否可接受，再把一件物品移走，检查原位置和遮挡区域。两项都通过才进入动画阶段。

**资料入口：** [S01][S01] [S02][S02]

<a id="T04"></a>
### T04 · 深度图与微视差：让照片拥有一点空间

**先做小样** · 制作端＋运行端 · 实现投入：中 · 补充调研

关键词：Depth Anything 3 / depth / 视差 / 2.5D

**想要的体验。** 指针或手指稍微移动时，近处与远处发生不同幅度的位移，像透过一扇小窗看回忆。

**依据与边界。** Depth Anything 3 提供单图深度等几何估计能力。具体输出和许可证因检查点而异；深度图本身不是可自由漫游的三维场景。 [S04][S04]

**实现思路（项目建议）。** 制作阶段估计深度，先看可视化结果并修正重要边界；约定数值越大代表越近还是越远。

将归一化深度转成有限的图像采样偏移，或把画面分为几张具有不同移动系数的平面。

镜头位移保持克制，给边缘预留余量；露出空洞时结合 T05 补背景，而不是继续加大位移。

**输入与产物。** 输入：画面。输出：深度数据／深度纹理、位移范围和边缘处理策略。深度是数据纹理，不作为普通颜色图处理。

**容易踩的坑。** 相对深度不能直接解释为真实米数；反光、透明和遮挡边界要单独验证。DA3-Base / Small 当前标为 Apache 2.0，多个更大检查点标为 CC BY-NC 4.0。 [S04][S04]

**更简单的替代。** 不用模型深度，人工划分远景、中景、近景，做受控的分层位移。

**最小验证实验。** 在四个方向移动视角，检查人脸／文字是否变形、边缘是否撕裂；减少动态模式下应可完整静态观看。

**资料入口：** [S04][S04] [S16][S16]

<a id="T05"></a>
### T05 · 遮挡补全：物件移走后，背景仍然成立

**按需采用** · 制作端 · 实现投入：中 · 前文整理

关键词：inpainting / 遮挡 / 背景补全 / 事实边界

**想要的体验。** 拿起信封、翻开纸张或移动镜头后，不出现空洞、重复轮廓或残留阴影。

**依据与边界。** 分层深度图像研究明确处理新视角下原本被遮挡区域的颜色与深度补全。这里引用其问题定义，不将 2020 年方法当作最新模型。 [S05][S05]

**实现思路（项目建议）。** 根据物件最大移动范围，圈出一定会暴露的区域；只补这部分所需的背景。

补好底图后，移走整件前景检查纹理连续性、阴影残留与重复物件，再放回前景核对组合。

若遮挡的是重要的真实人物、票据或文字，不把生成结果当作真实记录；改用设计性的留白或装饰遮挡。

**输入与产物。** 输入：原图、遮挡蒙版、移动范围。输出：干净底图，必要时还包括底图深度。

**容易踩的坑。** “看起来合理”不等于“真实发生过”。补全应服务于艺术化场景，不补造关键记忆。

**更简单的替代。** 改变物件动作，避免露出未知区域；例如让信封就地打开而不是整件移走。

**最小验证实验。** 把前景隐藏，单看底图，再从极限视角查看组合；所有允许的状态都不能露出未处理区域。

**资料入口：** [S05][S05]

<a id="T06"></a>
### T06 · AI 3D 资产：先确定要 Mesh 还是 Splat

**先做小样** · 制作端 · 实现投入：高 · 前文整理＋补充调研

关键词：TRELLIS.2 / SAM 3D Objects / GLB / PBR / AI 3D

**想要的体验。** 把一件有意义的实物变成可以转动、靠近观察或参与场景的数字物件。

**依据与边界。** TRELLIS.2 官方提供图像到带 PBR 材质资产及 GLB 导出示例；SAM 3D Objects 用于单图物体重建，其快速示例包含 Gaussian Splat 导出。不能把二者的所有输出都当成已经整理好的游戏资产。 [S38][S38] [S06][S06]

**实现思路（项目建议）。** 先定义动作：只是看看、绕一圈，还是必须打开盒盖。需要部件结构和常规材质编辑时，优先验证 Mesh 工作流。

生成候选后，在 Blender 中检查背面、薄片、孔洞、尺度、轴心、材质与部件；为关键动作重新整理几何。

控制面数和纹理后再导出，分别在浏览器与参考画面中核对。Splat 路线转到 T13，不强行冒充网格。

**输入与产物。** 输入：物体图像及必要提示。输出：清理后的 GLB／纹理，或明确格式的 Splat 资产。

**容易踩的坑。** 单图不可见的背面只是推断。TRELLIS.2 官方当前要求 Linux 与至少 24 GB NVIDIA 显存；这是制作端条件，不是接收者条件。MIT 模型／代码也不覆盖所有依赖的独立条款。 [S38][S38]

**更简单的替代。** 对简单杯子、盒子手工建模；或直接渲染成多个视角的图片，以图片切换代替实时 3D。

**最小验证实验。** 先让一件物品在目标手机上旋转，再检查最不利视角、材质、载入与持续运行；通过后才增加第二件。

**资料入口：** [S38][S38] [S06][S06] [S14][S14]

<a id="T07"></a>
### T07 · HTML／SVG 遮罩与纸面叙事

**默认优先** · 运行端 · 实现投入：低—中 · 前文整理

关键词：SVG / CSS / mask / clip-path / 纸张 / 文字

**想要的体验。** 实现信纸展开、笔迹显露、非矩形照片、地图路线和纸张拼贴，而不是卡片列表。

**依据与边界。** CSS clipping 用路径裁切可见区域；mask 可以表达渐变透明度，也可使用 SVG 资源。 [S07][S07]

**实现思路（项目建议）。** 把正文保留为 HTML，将纸张与装饰作为视觉层；以 SVG 路径或透明纹理定义纸边与揭示区域。

通过一个明确的进度值控制遮罩、位移与透明度；少量动作可用 CSS，复杂顺序再接 T15。

文字出现后进入可稳定阅读的布局，不让正文继续跟随大幅视差。

**输入与产物。** 输入：SVG 路径、纸张纹理、正文。输出：语义化页面与遮罩动效。

**容易踩的坑。** clip-path 和 mask 不是同一种运算；Alpha 遮罩也不等于黑色遮住、白色显示。软边与复杂合成需要实机核对。

**更简单的替代。** 直接显示完整纸面，用简单位移／淡入替代复杂遮罩。

**最小验证实验。** 检查手机换行、字体放大、键盘顺序；关闭动画后仍能读完所有内容。

**资料入口：** [S07][S07]

### T08 · PixiJS 分层舞台：一幅可探索的插画

### T11 · 图像粒子：散开、聚拢与重新拼合

**按需采用** · 运行端 · 实现投入：中—高 · 前文整理

关键词：粒子 / ParticleContainer / 图片重组 / GPU

**想要的体验。** 让散落的字迹或碎片最终组成一张真实便条，把“重新拼起”变成一个叙事时刻。

**依据与边界。** PixiJS 的轻量粒子容器可组织大量简单视觉元素；官方对 Particle API 仍保留实验性接口提示，应锁定版本。 [S11][S11]

**实现思路（项目建议）。** 制作阶段从目标图的非透明区域采样，保存每个粒子的目标位置、颜色与固定随机种子。

**输入与产物。** 输入：目标图片与采样规则。输出：粒子数据、重组动效和清晰终帧。

**更简单的替代。** 使用少量图片碎片或遮罩显露；减少动态模式直接显示终帧。

**最小验证实验。** 重复触发和跳过后都能回到相同终态；最终文字清楚，粒子不会一直占用计算。

关键词：Rive / 向量动画 / Data Binding / 角色 / 互动图形

**想要的体验。** 制作会响应拖动、点击或进度变化的纸盒、图形角色和小型插画组件。

**依据与边界。** Rive 可在设计端定义动画状态机，并通过 Web 运行时的数据绑定等机制控制表现；不只是播放固定时间轴。 [S24][S24] [S25][S25]

**实现思路（项目建议）。** 把一个局部物件作为独立 artboard，先在设计端做好静止、响应和完成姿态。

约定少量稳定的数据属性，例如打开程度、是否选中；让程序改变属性，而不是耦合所有内部动画细节。

将它接到全局叙事状态，测试缩放、透明背景和资源生命周期。

**输入与产物。** 输入：Rive 源文件、导出的 .riv 与数据契约。输出：可以嵌入作品的互动组件。

**容易踩的坑。** Rive 的局部动画状态机不等于整个故事的状态机；设计端与运行时版本要匹配。复杂写实插画未必适合全部重画成此路线。

**更简单的替代。** 少量 SVG ＋ CSS／GSAP，或预渲染动画。

**最小验证实验。** 连续改变属性和多次加载／销毁后表现正确；减少动态模式下有静态替代。

**资料入口：** [S24][S24] [S25][S25]

### T20 · 响应式构图：同一故事，两套舞台摆放

**默认优先** · 制作端＋运行端 · 实现投入：中 · 前文整理

关键词：移动端 / 响应式 / art direction / 布局

**想要的体验。** 手机上仍然像经过设计的作品，而不是把一张横向大图缩成看不清的小图。

**依据与边界。** MDN 将响应式图像区分为分辨率切换与 art direction；后者就是针对不同布局提供合适构图。下面的场景做法是针对本项目的扩展建议。 [S27][S27]

**实现思路（项目建议）。** 共用物件与叙事状态，为横向和竖向分别记录位置、缩放、留白与焦点。

对交互物件设置安全区域；背景可裁切，但不能裁掉唯一操作入口。屏幕尺寸变化后重新计算命中位置。

重要文字进入独立阅读层；旋转屏幕时保留当前故事进度，而不是从头重播。

**输入与产物。** 输入：公共资产与横／竖构图数据。输出：不同尺寸下的同一体验。

**容易踩的坑。** 仅依赖 CSS cover 或统一缩放通常不够完成构图决策；浏览器地址栏变化与安全区域需实机观察。

**更简单的替代。** 为手机设计顺序式近景页面，不强求显示整个桌面。

**最小验证实验。** 测试至少一个窄屏、一个大屏和横竖切换；文字、控件、物件和命中区域不互相遮挡。

**资料入口：** [S27][S27]

<a id="T21"></a>
### T21 · 性能资产管线：把质量做在预算之内

**默认优先** · 制作端＋运行端 · 实现投入：中 · 前文整理＋补充调研

关键词：性能 / 纹理 / KTX2 / GPU / 自适应画质

**想要的体验。** 接收者打开后流畅、清楚，不因大图片、滤镜和内存峰值破坏体验。

**依据与边界。** PixiJS 与 MDN 均强调纹理、滤镜、绘制缓冲区等成本；Three.js KTX2Loader 可把相应纹理转码为设备支持的 GPU 压缩格式。 [S13][S13] [S28][S28] [S29][S29]

**实现思路（项目建议）。** 建立低／中／高画质档，控制图片分辨率、画布像素倍率、粒子数和后处理；先加载当前场景真正需要的资源。

区别下载体积和解码后内存：普通 RGBA8 纹理可先用 `宽 × 高 × 4 字节` 估算单层基础开销，mipmap、临时缓冲和副本另算。

先缩小无用分辨率、裁透明留白、减少滤镜区域；3D 路线再评估 KTX2 与几何优化，不能只换扩展名。

**输入与产物。** 输入：源素材、目标设备和渲染测量。输出：分级资源包、加载策略与质量档。

**容易踩的坑。** 没有通用的“安全粒子数／安全贴图数”。KTX2 转码器、WASM 和所需能力检测也须随作品部署；透明纹理压缩要检查边缘。

**更简单的替代。** 保留主画面与交互，关闭环境特效、减少纹理和渲染像素；最底层提供静态阅读版。

**最小验证实验。** 冷启动、切换场景和持续运行分别测；记录帧时间、可见卡顿、内存趋势及峰值资源，而不只看平均 FPS。

**资料入口：** [S13][S13] [S28][S28] [S29][S29]

<a id="T22"></a>
### T22 · 可访问性与减少动态：不让美感变成门槛

**默认优先** · 运行端 · 实现投入：低—中 · 前文整理

关键词：accessibility / prefers-reduced-motion / 静音 / 键盘

**想要的体验。** 不擅长操作、不能开声音或不适合强运动效果的人，也能完整收到这份表达。

**依据与边界。** prefers-reduced-motion 可读取系统减少非必要运动的偏好；它需要你的 CSS 与运行逻辑主动响应，不会替你关闭所有画布动画。 [S30][S30]

**实现思路（项目建议）。** 为重要动作提供点击／按钮或键盘等价路径；关键文字与静音、退出等控制保留语义化 HTML。

减少动态时关闭视差、大幅缩放与粒子飞行，直接呈现对应稳定状态；不要连信息一起删除。

将音频内容的必要信息写成文字，保证颜色不是唯一提示，并保留可见焦点。

**输入与产物。** 输入：交互与内容清单。输出：完整模式、减少动态模式与无声／替代操作路径。

**容易踩的坑。** 这里是项目验收建议，不是完成几项检查就能宣称满足某个正式合规级别。

**更简单的替代。** 一个排版良好、顺序可读的静态版本。

**最小验证实验。** 只用键盘、关闭声音、开启减少动态后各走完整条流程；核心表达不能丢失。

**资料入口：** [S30][S30] [S23][S23]

### T23 · 静态交付与收藏：链接、离线、备份是三件事

**默认优先** · 构建与交付 · 实现投入：中 · 前文整理＋补充调研

关键词：Vite / 离线 / 归档 / Service Worker / 静态托管

**想要的体验。** 作品不仅当天能打开，也能以清楚的方式留存，而不是只剩一个可能失效的地址。

**依据与边界。** Vite 可生成静态构建并配置资源 base；模块在 file:// 下存在加载限制。Service Worker 的离线机制需安全上下文，浏览器缓存也可能被清理。 [S31][S31] [S35][S35] [S32][S32] [S36][S36]

**实现思路（项目建议）。** 在线版用 HTTPS 静态托管，使用正确资源路径；把资源与解码器随版本管理，避免依赖临时 CDN 地址。

离线版明确选择：可本地启动的完整资源包，或专门打包并实际测试过的单文件版本。不要承诺 Vite dist 双击即用。

归档同时保存源素材、最终正文、源项目、锁文件、操作说明，以及静态图／视频等易观看备份。

**输入与产物。** 输入：构建产物与源项目。输出：在线作品、注明运行方式的归档包、易观看备份。

**容易踩的坑。** 浏览器缓存不是永久收藏；源码保留也不是永久可运行保证。交付给对方的私人内容仍须遵守约定分享范围。

**更简单的替代。** 直接保留静态图册／视频与正文，即使实时交互失效也能阅读。

**最小验证实验。** 断网测试承诺的离线路径；换一个目录测试资源；在不依赖开发机服务的环境中重现启动步骤。

**资料入口：** [S31][S31] [S35][S35] [S32][S32] [S36][S36]

<a id="T24"></a>
### T24 · WebGPU 与 TSL：按效果需求升级，不按热度升级

**实验储备** · 运行端 · 实现投入：高 · 前文整理＋补充调研

关键词：WebGPU / TSL / Three.js / compute / WGSL

**想要的体验。** 当大量 GPU 运算或复杂程序化效果真的成为需求时，为进一步实现保留路线。

**依据与边界。** Three.js WebGPURenderer 支持 WebGPU，并能回退到 WebGL 2；TSL 是其节点着色工作流的一部分。旧 ShaderMaterial、RawShaderMaterial 和 onBeforeCompile 自定义不能直接照搬。 [S33][S33]

**实现思路（项目建议）。** 先写一个独立效果实验，列明依赖哪些渲染／计算能力；检查所需材质、后处理与插件是否支持目标后端。

用 TSL／节点材质实现适合双后端的部分，主动强制 WebGL 测回退；原生 WebGPU 专用能力另设替代。

保留与主作品隔离的实验分支，达到效果与设备验收后再替换，不先迁移全部工程。

**输入与产物。** 输入：需要被验证的 GPU 效果与目标设备。输出：能力清单、兼容测试与降级分支。

**容易踩的坑。** 渲染器能回退不等于每个特效、计算路径与第三方库都能回退。PixiJS 的当前生产建议和 Spark 的集成路径都应分别检查。 [S08][S08] [S18][S18]

**更简单的替代。** WebGL 实现、预计算轨迹、预渲染，或减少对象数量；保留叙事，不强行保留技术。

**最小验证实验。** 分别测试 WebGPU、强制 WebGL 2、初始化失败与缺少某特性的设备；不能只有开发机演示。

**资料入口：** [S33][S33] [S08][S08] [S18][S18]

<a id="recipes"></a>
## 03 · 五组组合配方

以下均是**尚待制作的设计配方**，不是已经完成的演示。示例情节只用于说明技术，不代表用户实际经历。每组都先做一个完成度足够高的短片段。

### R01 · 雨天窗边的一封信

**体验。** 先看到安静桌面，拿起一件物品，打开一封信，最后停留在可读的文字里。

**组合。** T01 美术目标 → T03 分层／T02 抠图 → T05 补底图 → T08 舞台 → T10 局部雨玻璃 → T15 时间线 → T18 声音。

**制作顺序。** 先交付静态主画面和干净底图，再做一件物品的拾取／放回，最后才加雨、光和音频。信件正文独立排版，阅读时暂停非必要大运动。

**真正需要复用的能力。** 场景加载、物件拾取、阅读层、音频总开关；每次作品的物件意义、构图与叙事顺序重新决定。

**第一道验收。** 不开声音、不加雨效，单靠拿起与展开这一段动作，是否已经自然、完整？

### R02 · 一张总会走错的旅行地图

**体验。** 点选路线或移动一个小标记，沿途遇到已确认的真实片段；“走错”是故事的一部分，而不是对用户的惩罚。

**组合。** T07 SVG 地图或 T08 插画地图 → T16 路线状态 → T17 点击／拖拽 → T15 地图转场 → T18 声音。

**实现要点。** 路线、视觉地图与故事节点分开存储；节点记录进入条件、已经看过与返回行为。拖拽可以用点击替代。路线判定用图或节点，不依赖对整张插画做复杂物理碰撞。

**降低成本。** 不先引入真实地图平台、定位或开放世界；手绘路线本身就可以承载这段旅行。

**第一道验收。** 三个节点已经能表达一个明确感受，且不会让接收者迷失在操作规则中。

### R03 · 把两张票重新放在一起

**体验。** 两张票靠近时吸附，背面的文字或图案终于连成完整表达。

**组合。** T02 / T03 取出素材 → T17 拖拽吸附 → T16 拼合状态 → T15 聚焦 → 可选 T11 粒子收束。

**实现要点。** 视觉位置与逻辑完成条件分开；完成后吸附到明确布局，再允许翻看。使用经过确认的票面和文字，不让生成模型重写事实。

**降低成本。** 先不要粒子，只测试两张票的抓取偏移、吸附位置、声音和终态。动作已经成立后，再比较是否值得加入特效。

**第一道验收。** 点击替代拖拽也能到达同一结果；重复拼合、取消、重播不会出现重复文字或声音。

### R04 · 一件可以打开的微缩礼物

**体验。** 用户轻微转动一只盒子，打开盒盖，里面不是功能菜单，而是一个重要细节。

**组合。** T06 AI 辅助物体制作或手工建模 → T12 固定机位 3D → T15 开合时间线 → T16 状态 → T18 声音。

**实现要点。** 先明确盖子的部件和旋转轴；生成出的单体外观不等于已经有可开合结构。静态背景可烘焙，活动部分的阴影单独处理。

**降低成本。** 对简单几何手工制作可能比修理生成网格更直接。完整实时 3D 没有必要时，输出几个固定视角与开合视频。

**第一道验收。** 从允许的每个角度看都成立；盒盖与内容不穿插，材质不与目标画风冲突。

### R05 · 回到某个空间的一角

**体验。** 在一个空间片段中停留，点击几件有意义的物品进入故事。

**组合。** 有合适来源的空间资产 → T13 Splat 展示 → 独立热点／代理几何 → T16 叙事 → T20 手机构图。

**实现要点。** 摄影记录与生成式推断明确区分；先裁成一个受控的小区域，而不是允许接收者走到未记录的位置。

**降低成本。** 视觉重建用来观看，物件逻辑单独建立。遇到画质或设备问题，退回限定镜头视频和可点击画面。

**第一道验收。** 这份空间感是否带来不可替代的意义？如果与一张好照片相比没有增益，不必采用 3DGS。


<a id="architecture"></a>
## 04 · 最小工程组织

下面是建议性的组织方式，不是需要预先实现的平台。核心分界是：**制作端负责生成与审核，运行端负责确定性地呈现与交互。**

### A. 制作端：从素材到可控资产

`经历与素材 → 目标画面 → 分层／补全／建模 → 人工检查 → 面向设备的优化 → 交付资产`

尽量把 AI 放在这里。一个候选资产经过挑选、修改和确认后，再进入作品。接收者打开时不必等待模型，也不必承受临场生成带来的内容漂移。对制作成本的判断应记录总重试与人工修整，不只记录一次推理时间。

### B. 运行端：三层逻辑即可起步

**内容与资产层：** 真实正文、图片、声音、布局和来源引用。  
**交互状态层：** 当前场景、允许动作、事件与完成条件。  
**表现层：** 画面、声音、时间线与阅读界面。

这是一种职责划分，不要求三个大框架。不要把故事逻辑写进每一张图片的动画回调里，也不要让切换画质重置故事进度。

### C. 建议目录

```text
project/
  art-source/          原始美术与制作源文件；不默认公开部署
  provenance/          素材来源、事实确认与使用范围；不默认公开部署
  assets/              经审核、优化后的运行资产
  scenes/              布局、内容与物件配置
  runtime/
    state/             事件、状态与转换
    view/              场景渲染与阅读层
    motion/            时间线与局部效果
    audio/             音轨与播放控制
  tests/               行为测试与视觉基准
  archive/             交付说明、最终正文、易观看备份
```

这不是建议现在就建立大型“生成作品引擎”。第一个场景可以更简单；出现第二次真实复用需求时，再抽取共用部分。

### D. 一件物品的最小数据契约

下面是**字段示意**，不是现成引擎 API，也不包含实际图片。坐标约定由项目确定后保持一致：`position` 为归一化场景坐标，`pivot` 为纹理内归一化轴心，`width` 为相对场景宽度。

```json
{
  "id": "envelope",
  "asset": "assets/envelope.webp",
  "pivot": [0.5, 0.7],
  "zIndex": 20,
  "layouts": {
    "landscape": {"position": [0.60, 0.67], "width": 0.22},
    "portrait": {"position": [0.50, 0.64], "width": 0.48}
  },
  "hitArea": {
    "type": "ellipse",
    "center": [0.5, 0.5],
    "radii": [0.55, 0.55]
  },
  "interaction": {
    "pointerAction": "open",
    "alternativeAction": "button-open",
    "reducedMotionAction": "show-letter"
  },
  "shadowAsset": "assets/envelope-shadow.webp",
  "contentRef": "letter-01",
  "provenanceRef": "asset-017"
}
```

`provenanceRef` 指向制作端记录，不应把访谈原文、私人照片全集或服务密钥打进公开前端。状态机在运行层统一管理，不为每个物件随意添加相互矛盾的“已打开”字段。

### E. 值得沉淀什么，不值得过早固定什么

| 适合复用 | 应保留为每件作品的创作 |
|---|---|
| 资源加载、拾取／放回、阅读层、音频总开关 | 为什么要拿起这个物件、先看到谁的哪段话 |
| 遮罩、网格、视差和局部滤镜的参数接口 | 哪种形式属于这段经历，什么应该动、什么该静止 |
| 响应式布局、减少动态、归档与测试流程 | 构图、节奏、情绪与故事结构 |
| 分层／建模后的清理和验收流程 | 真正值得留下的那个细节 |


<a id="validation"></a>
## 05 · 验证与取舍

### 不靠工具名单判断项目是否成立

**先过静态关。** 目标画面与主要阅读页在手机、桌面上都成立。  
**再过单动作关。** 一个拿起、翻开或拼合已经自然，且能取消、重复和跳过。  
**最后过完整片段关。** 从打开作品到停留阅读，不依赖开发者解释，也不靠大量装饰遮掩问题。

只有这三关通过，才值得扩展第二个场景。先进技术不负责拯救还没设计好的画面。

比较“人工三层视差”和“自动深度视差”时，不只问哪个更先进。要问：在自己的素材上，哪一种更自然、修整更少、手机效果更稳、以后更容易复现。

### 最小测试矩阵

| 维度 | 应实际走过的情况 | 重点观察 |
|---|---|---|
| 输入 | 鼠标、触摸、键盘／按钮替代 | 抓取偏移、取消、命中区域、无悬停也可发现 |
| 状态 | 重复点击、快速关闭、重播、资源失败 | 没有冲突时间线、丢失物件或不可达的阅读内容 |
| 环境 | 冷启动、弱网、后台再回来 | 首帧、资源缺失提示、声音与动画恢复 |
| 画面 | 窄屏、横屏、旋转、字体放大 | 关键物品未裁掉，文字不被特效覆盖 |
| 感官 | 静音、减少动态 | 表达与信息完整，不是空白或阉割版本 |
| 性能 | 切换场景与持续停留 | 帧时间波动、资源峰值、持续内存增长 |
| 交付 | 非开发机、约定的离线方式 | 资源路径、启动说明、无临时服务依赖 |

Playwright 可以模拟视口、触摸和媒体偏好，用于部分自动化回归；但这里仍建议补充真实手机验收，不以桌面模拟代替发热、GPU 与系统浏览器行为测试。[S34]

### 性能数字如何记录

不要事先写“所有手机 60 FPS”或“支持十万粒子”。若目标为 60 FPS，一帧总时间约为 16.7 ms；30 FPS 约为 33.3 ms，这是时间预算换算，不是本项目已达到的指标。

记录目标设备、分辨率／画布像素倍率、运行场景与持续时间，观察最差时刻而不只看平均值。纹理与绘制缓冲区的管理依据见官方实践。[S28]

### 何时不用一项技术

当它没有带来新的表达、只在开发机成立、需要反复修理不可控素材，或会迫使接收者学习操作时，退回简单路线不是失败。把原因记进实验卡，技术库才会逐渐包含你们自己的判断，而不只是外部工具说明。

### 私密作品：入口与素材都要考虑

只在前端藏一个密码，不等于限制了图片、音频和正文的访问。OWASP 的授权实践要求不能仅依赖客户端检查；这意味着真正私密的交付需要保护对应资源，而不只是隐藏界面。[S37]

本项目建议默认不公开原始访谈和未采用的照片，不把个人敏感信息写进页面元数据。采用真实访问控制或明确的私下交付方式；即使有访问控制，也不承诺阻止接收者录屏或转发已经看到的内容。

使用第三方模型／服务处理私密素材前，应先确认相关人的使用范围与服务的数据处理约定。此处不对尚未指定的服务作隐私保证。

### 复现与收藏

记录直接依赖版本和锁文件；实验性 API 尤其需要固定版本。记录模型、检查点、参数、人工修整与导出方式。最终交付同时保留容易观看的正文与图像／视频版本，避免把收藏完全寄托于一个在线链接。[M01]

## 07 · 如何维护这份库

**Markdown 是内容原稿，HTML 是本版阅读快照。** HTML 可搜索技术卡片、按类别与采用建议筛选；修改 Markdown 不会自动同步 HTML，需要重新生成阅读版。

先查体验索引，再读对应卡片，然后选一个最小实验。不要把 24 项技术都变成首作待办。实际开发时，把“本轮文档核验”与“项目实测通过”分开记录。
