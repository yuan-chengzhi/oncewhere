# 《月背拾遗司》：生成式体验与不同作品形式的技术研究

查阅日期：2026-09-21。范围：官方产品／API 文档、原始研究与官方开源仓库。本文是技术研究与实验设计，没有调用付费生成服务、运行外部模型或改动应用。官方能力、评审判断、实验目标分开记录；下列延迟均注明来源，不是本环境实测。

**建议同时准备两个有明显形式差异的样片：可停留的双人互动短片，以及以等待和回应构成的音乐小剧场。** 前者用预生成影像解决角色表演，后者用可控音符／声音生成改变玩家的参与方式。空间生成与实时角色可做第二轮；实时生成整片世界目前不宜承担主线的物件状态与保存承诺。

这不是坚持现有网页机关。假如新形式能使人更清楚地看见两人的关系，就应允许换媒介与技术栈；也应允许实验结果证明不需要即时生成。

**交付范围已更新：用户明确接受下载安装与配置，由我们完成打包。** HTML、单文件、当前 8.66 MiB 体积与移动浏览器均不再是选型前提；桌面应用、引擎作品、本地声音装置和普通音视频备份都可成立。具体接收设备仍决定发行目标，但不能因为当前实现是网页就提前淘汰更合适的形式。

## 先分清四种“实时”

| 路线 | 播放时实际发生什么 | 玩家获得的能力 | 保存边界 |
|---|---|---|---|
| 预生成影像＋本地镜头调度 | 播放已验收的视频，按状态选择、停留或转场 | 改变停顿、观看次序、局部视点 | 可保存全部镜头和调度程序；它是互动影片，不是即时视频生成 |
| 预生成三维环境＋本地渲染 | 浏览器或引擎重绘固定空间，更新灯／物件／角色 | 真正改变视点和物件位置 | 保存场景资产、程序和状态后可重访；不是模型逐帧创造新世界 |
| 实时音乐／角色生成 | 操作不断影响模型输出的声音或会话 | 没预写完的音乐或对话回应 | 可以录下本次结果；同样输入不等于逐采样／逐句复现 |
| 实时生成世界 | 视图随输入持续由世界模型生成 | 在生成环境中移动探索 | 下载录像只保存看过的路线，不等于拥有可离线运行的世界 |

后两项的独特价值是新回应；前两项的独特价值是经过导演选择的表演与可稳定保留的世界。应比较具体的表达增益，不能用“实时”一词混同这些路线。

## 路线一：预生成角色表演，制作可停留的互动短片

**可用事实。** Veo 3.1 在 Gemini API 提供图生视频、首尾帧控制及最多三张参考图，模型页标为 Preview；生成任务异步完成。官方列出的请求延迟为 11 秒至高峰期 6 分钟，视频需在两天内下载。其 seed 不保证确定性；官方只称英语已完整支持，其他语言未评估。[Veo 3.1 官方 API 文档](https://ai.google.dev/gemini-api/docs/veo?hl=en)

Runway 的 Act-Two 将表演视频转移给角色参考图／视频，支持最长 30 秒；角色图可获得手势控制，官方说明适用于多种风格和非人角色。它当前以单角色输入工作；官方双角色教程要求分别驱动、裁切后再合成，并非一次生成就理解两人接物。[Act-Two 官方操作说明](https://help.runwayml.com/hc/en-us/articles/42311337895827-Performance-Capture-with-Act-Two)；[官方双角色工作流](https://help.runwayml.com/hc/en-us/articles/41748090660499-Creating-Multi-Character-Dialogues-with-Act-Two)

**对本作的增益判断。** 现有插画已经有明确的外形与光线。与其让整幅背景漂移，更值得演出狐狸停手、小狗托住月牙、目光确认、狐狸接过灯的次序。图生视频适合整体运动与镜头；表演迁移适合先由人导演出犹豫、等候和回答。两者都没有替我们决定该演什么。

**可控性与中文。** 首尾帧、参考图与录制表演是控制条件，不能保证手指、狐狸口鼻、扣件孔距或衣领星星在中间帧正确。第一轮用无声表演和已有中文字幕；中文对白若后续加入，应独立录制／配音并验收，不把 Veo 的其他语言“可能可用”写成中文保证。不要让视频画出关键中文标签；将标签作为准确的后期层。两人交接物品最易暴露遮挡与物件身份变化，正应作为压力测试，而非避开它只挑漂亮风景。

**延迟、复现与交付。** 生成等待发生在制作阶段。把选中的镜头下载、剪辑、固定版本后，运行时无需等模型。首尾帧相同不等于运动速度和光线自然衔接，要人工审镜头。Runway API 输出 URL 官方注明会在 24–48 小时失效，应保存实际文件。[Runway 输出说明](https://docs.dev.runwayml.com/assets/outputs/) 收藏版可以交付本地镜头包及普通视频导出；不能再预设沿用当前 8.66 MiB 单文件体积。

**许可事实。** Runway 帮助页表示其不对用户生成内容设置非商业限制，双方之间用户保有其权利；这不是第三方素材权利的担保。[官方商业使用说明](https://help.runwayml.com/hc/en-us/articles/21668707517587-Can-I-use-the-content-I-made-in-Runway-for-commercial-purposes) Google API 条款表示 Google 不主张生成内容所有权，但保留给其他人生成类似内容的可能；不能据此声称生成物具有独占版权。[Gemini API 条款，2026-03-23 生效](https://ai.google.dev/gemini-api/terms)

**本会话。** 有静态图像生成／编辑工具和命令执行工具，可制作参考帧、分镜、后期与播放器。没有已提供的 Veo／Runway 视频生成工具，也没有已确认的 API 账户与凭证；不能把 imagegen 当作视频模型。Act-Two 还需要实际的驱动表演输入。本轮没有声称已经生成样片。

## 路线二：让“等你说完”变成可演奏的声音关系

这里有三个成熟度不同的实现层，可以制作同一段内容再比较，不必先选最复杂的一层。

### 2A. 固定音乐材料＋确定性的响应调度

**本作已具备的事实。** 当前有可编辑 [MIDI](../assets/audio-source/moon-office-theme.mid)、[195 事件谱面](../assets/audio-source/score.json) 与 Web Audio 播放层。它们可以作为重新配器的来源，但现在发布的是单个混合音轨，没有现成的可独立控制分轨。

**实验建议。** 从现有主题写出“提问”“留空”“回答”三个短材料；玩家敲出的间隔决定对方什么时候接句，角色的姿态与这个时间一致。先把声音试听到成立，再测试生成式版本是否增加有意义的变化。固定材料能精确保留旋律、时机与回放；这种响应音乐即使不使用 AI，也已不同于全程单曲循环。

### 2B. Magenta RealTime 2：本地、音符可控的生成乐器

**可用事实。** Google 于 2026-06-04 发布 MRT2；官方说明支持文本、参考音频与 MIDI 控制，标称控制延迟约 200ms，音频帧 40ms。这里的 200ms 是作者报告，不是本作可直接承诺的整件作品端到端延迟。[官方发布与技术说明](https://magenta.withgoogle.com/magenta-realtime-2)

官方仓库提供 Python 与 C++／MLX 路线；230M 小模型面向 Apple Silicon 实时运行，2.4B 模型对硬件要求更高。Linux／NVIDIA 可走 Python／JAX 的离线生成，不能把这一支持写成已经在任意电脑或手机浏览器实时运行。[官方仓库](https://github.com/magenta/magenta-realtime)；[安装说明](https://github.com/magenta/magenta-realtime/blob/main/docs/installation.md)

**增益判断。** 这是比“换一首 AI 配乐”更值得试的技术：可以把本作两位角色的短动机写成 MIDI，让玩家控制留白与交接，让模型处理音色／织体的变化。是否能始终保住短动机、是否会突然冒出多余鼓点、句子结束是否干净，都仍要测；MIDI 输入是控制条件，不是逐音正确的验收结果。

**中文、一致性、许可。** 它面向器乐，不用于生成狐狸和小狗的中文台词；中文界面与字幕可独立存在，中文提示质量本轮未验证。模型卡区分代码 Apache 2.0 与权重 CC BY 4.0，并说明 Google 不主张用户输出权利；其偶发人声主要是非词汇性发声，不能当作中文歌唱系统。[官方模型卡与使用条款](https://github.com/magenta/magenta-realtime/blob/main/MODEL.md)

**复现与保存。** 建议同时保存固定版本模型信息、MIDI／控制事件及实际 PCM／FLAC；后者保存这一夜真正发生过的声音。相同 seed、控制日志和模型版本也不能未经测试就承诺跨硬件逐采样复现。MRT2 可直接成为本地 Mac 装置的声音运行时，也可只用于制作阶段，之后把验收的音乐交给桌面播放器或引擎调度；两种交付对接收者硬件的要求完全不同，详见下方打包方案。

**本会话。** 当前机器查得为 x86_64，PATH 未发现 `nvidia-smi`，没有验证可用 GPU；这不等于证明硬件绝无 GPU，但不具备直接承诺 MRT2 实时样片的依据。可准备接入代码与事件格式；未安装／运行模型，未试听输出。

### 2C. Lyria RealTime：云端流式音乐试验

**可用事实。** 官方将其标为实验模型，通过 WebSocket 持续生成器乐，支持加权提示、密度、亮度、调式等控制。变更 BPM 或调式需要重置上下文，会有硬转换；官方要求做好缓冲以处理网络波动。文档没有给本作能采用的端到端毫秒 SLA。[Lyria RealTime 官方文档](https://ai.google.dev/gemini-api/docs/realtime-music-generation)

**增益与边界判断。** 适合试“走近柜台，音乐变稀；两人回应时短暂合流”的渐变，不应把它当成精确控制每个扣合音的系统。中文不依赖歌声；提示语言效果未知，先用固定英文音乐标签。维持本作主题最直接的方式仍是独立保留已写好的动机；仅用风格文字控制是否能维持身份需试听。实时版还要处理断线、重连与已缓冲音频：发出停止提示不意味着扬声器立即静音。

**保存、许可与本会话。** 流式 PCM 可以由实现层录存，未来重访播放录音是确定的，但再次生成不是同一表演。适用 Google API 条款，不能从“实验／免费可试”推导无条件部署权；所查条款还限定 API 客户端的年龄与区域，若后续决定面向儿童，应重新选择运行方式。本会话无已提供的 Lyria 调用工具与已确认凭证。该路线可作接入实验，不是当前已能交付的音乐成果。

## 路线三：生成一个真正能回来走动的柜台空间

**可用事实。** World Labs 的 World API 于 2026-01-21 宣布公开，接受文字、图片、全景、多视图与视频，异步返回可探索三维环境。[官方发布](https://www.worldlabs.ai/blog/announcing-the-world-api) Marble 可导出 splat／网格；它生成的是可继续加工的空间资产。Spark 是 World Labs 的 MIT 开源 Three.js 渲染器，可混合 splat 与网格。[Marble 介绍](https://www.worldlabs.ai/blog/marble-world-model)；[Spark 官方仓库](https://github.com/sparkjsdev/spark)

**增益判断。** 让玩家沿自己留灯的路径回来，转头还看见原来那盏灯，是空间形式才擅长表达的记忆。生成式空间能降低场景起稿成本；之后用本地程序明确记录灯位置、软布位置与柜门状态。要用独立可编辑资产表示两位角色、胸针和灯，不能假设整片生成 splat 自动拥有“可拿起的月牙”“有双孔的扣件”与正确碰撞。

**可控性、中文与延迟。** 此路线的可控性来自生成后固定和编辑资产；不是游玩时不断询问模型“这里该有什么”。生成延迟本轮未实测，也没有采用博客案例的速度作为保证。运行时性能要测实际场景与所选桌面／装置设备；若另做手机版再验收手机，Spark 的设备覆盖宣传不能替代测试。中文标牌由 UI／贴图层制作；在新视角下是否仍是原来的狐狸、小狗和第七号柜未知，建议首轮空间只生成环境。

**许可与保存存在需明确的文档差异。** 所查导出页称免费方案不能导出，Standard 可导出 splat／全景／碰撞网格，Pro 包含高质量网格和商业权；所查服务条款又按 Paid／API 概括输出使用权，具体订单仍可限制。不能据其中一句笼统写成“任意付费档均满足交付”，应以实际生成时的方案、导出项目和订单约定共同核对。免费时生成的结果升级后也不自动改按付费时权利处理。[导出文档](https://docs.worldlabs.ai/marble/export/gaussian-splat)；[服务条款 §3.3](https://www.worldlabs.ai/terms-of-service)

下载资产、记录运行库版本与状态后，可以设计本地收藏包；只有在线分享链接不够。本会话能编写／运行渲染原型，但没有已确认的 World API 凭证，也没有本作生成好的三维场景；不能声称已经能把现有画面无损变成可游玩空间。

## 路线四：会回应的角色，适合另一种作品核心

**可用事实。** Runway Characters 已提供自定义形象、声音、性格与知识的 Avatar，实时会话通过 WebRTC，API 文档给出单次最长 5 分钟。可取转录，存在录制时可下载录像；下载链接是临时的。[Characters API 核心概念](https://docs.dev.runwayml.com/characters/concepts/) 网页试用会话最长 2 分钟，与 API 时长不同；官方称主要测试英语，其他语言也支持。[官方产品帮助](https://help.runwayml.com/hc/en-us/articles/49557780326163-Runway-Characters)

**判断。** 它适合“一位夜班员听你描述遗失物，并和你共同写一张登记卡”的新作品。它不会自动增强本作两位角色之间的关系：用户加入对话后，核心很容易从旁观两人共同值班，变成“角色陪我聊”。这是一种值得单独立项比较的形式，不能当作纯粹画面升级。

**边界与实验方向。** 形象参考能建立外观基准，无法保证狐狸口鼻与表情始终稳定；中文节奏、打断、沉默、人格一致性、回应延迟都需实测。由应用保存案号、标签和已发生事件，让角色读这些事实；不能让自由生成对白决定“过去记录是否改变”。录像和转录可归档，下一次对话不会保证逐句相同。商用内容政策参见上述 Runway 官方说明；未看到中文质量保证或专门针对本作形象的可靠性数据。本会话无 Characters 调用工具或已确认凭证。

## 路线五：Genie 3／Project Genie 作为前沿对照

**可用事实。** 当前帮助页仍将 Project Genie 称为研究原型；面向符合地区条件的 Google AI Ultra 成年用户，可探索 60 秒。它允许下载本次录像，但“再访”是重新生成，可能不同；官方列有控制迟延、角色控制异常、世界／人物不完全服从输入等已知问题。[当前 Google Labs 帮助页](https://support.google.com/labs/answer/16875695) 模型页说明它是实时生成可探索环境的世界模型。[DeepMind Genie 3 官方页](https://deepmind.google/models/genie/)

**时点说明。** 2026-01-29 发布文只写美国 Ultra 用户，现行帮助页已写为 Ultra 可用地区；本研究采用现行帮助页描述，不把发布时的地区范围继续当作今天范围。[原始发布文](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/project-genie/)

**判断。** 它很适合用来探索“从柜台后走向月面”的运动想象，但本作的价值恰恰依赖回来以后物件还在同一个位置。若这项持续性不成立，世界的惊喜会损害收存的意义。没有在所查资料看到可用于本项目的公开通用生成 API、可导出的完整互动运行时或可离线再现同一世界的保证；中文提示与双角色长期一致性也未得到验证。

因此不应把演示录像称为可发布游戏。可访问性也不等于分发生成模型或嵌入自有网站的许可；本轮未核实这类授权。本会话没有 Genie 工具或已确认的订阅访问。

## 三种真正不同于现有点击解谜的作品方案

### 形式 A：一场可以多待一会儿的互动短片

玩家不解题，而是决定何时结束停留、把视线留给谁。一段固定的等待镜头让两人都在场；准备好以后，进入精心剪好的接灯和归途。控制作用在时间与注意，而非正确答案。按钮／键盘提供明确替代操作，停留不会变成必须憋住的 QTE。

导演先完成镜头关系，再用 Veo／Act-Two 或其他动画技术制作有限片段。安静状态可用分层实时动画，重要交接用预制镜头；这是一种混合媒介，可以更换整个现有弹窗结构。结尾导出用户这次的镜头版本与一份完整收藏包。

### 形式 B：两个人的一件乐器

玩家轻敲两三下或滑动一小段，狐狸发出短句；玩家停止输入，小狗听完再回答。再次靠近时两段动机重叠，月牙的裂缝在共同声音里亮起。没有节奏评分、抢拍失败或唯一旋律；关系表现为留空、接句与合奏。

确定性 MIDI／采样、MRT2 与 Lyria 可实现不同版本。完整乐句身份由作者设计，生成只负责经过验证的变化范围。将真正奏出的音乐留为录音，比结尾统一写“你们经历了一段回声”更具体。它需要音乐本身成立，不能靠漂亮波形代替听感。

### 形式 C：夜班结束后的可停留空间

玩家先与两位角色布置小范围柜台，之后可以慢慢走开、回头、再回来；灯与收藏位置真实保持。叙事来自视角、路径与共同安排，文字只有少量现场观察。Marble 可作为环境草稿，角色和关键物件仍需独立导演与状态。先限于一间房和一条短路，不把自由漫游规模当作完成度。

三种方案各自放大时间、声音、空间。应先比较哪一种最能保住“给共同的未来留一个位置”，再决定是否混合；不用把全部技术装进同一个作品。

## 接受安装后的交付方案：把制作端与体验端分开

**推荐。** 图生视频、表演迁移、空间起稿、大模型试音与反复生成优先留在制作端；体验者安装的是经过导演选择的镜头、音乐材料和本地状态程序。这样可以提高画面与声音的制作成本，而不要求每位接收者具有生成硬件。若音乐实验确实证明“当场生成的新回应”不可替代，再提供明确面向 Apple Silicon 的 MRT2 本地演奏版，或由我们配置好一台装置；不要把 Mac 的已知可行性泛化为 Windows／Linux 都能同样实时运行。

| 交付形态 | 我们制作／打包什么 | 体验者需要承担什么 |
|---|---|---|
| **互动影片桌面版，优先** | 原生播放器或引擎可执行程序、全部镜头、字幕、分轨音频、镜头调度与存档；按 Windows／macOS 等实际目标分别构建。另导出普通视频作阅读备份 | 安装空间、所选分辨率的视频解码与声音播放。无需 Veo／Runway 账户、生成模型或用于生成的 GPU；具体最低配置由最终包测试确定 |
| **固定材料音乐小剧场** | 在制作端用采样／MRT2／其他工具生成并验收材料；打包确定性的音符与乐句调度、角色动作和录音导出 | 普通音频／画面运行需求；用户端无需 MRT2。仍可以响应等待与敲击，只是材料已经写好 |
| **MRT2 本地实时演奏版** | 定制桌面应用、MLX／C++ 推理运行时、所选模型及全部资源、模型校验与录音保存；我们负责配置，不让用户手动搭 Python 环境 | 经实测的 Apple Silicon Mac、内存与磁盘预算；模型齐备后可设计离线使用。键盘／触控即可作为控制输入，不强制购买 MIDI 键盘 |
| **由我们配好的本地装置** | 随作品交付并配置 Mac 主机、控制界面和音频设备，版本冻结，开机启动 | 使用该装置；无需接收者自行选购或维护开发环境。设备采购与实体交付是独立预算，不暗藏在软件包承诺里 |
| **云端实时演奏／角色版** | 我们维护模型服务／第三方 API、会话与录音归档，客户端封装通信 | 持续网络连接和服务可用性；安装包本身不能消除云服务依赖。是否采用取决于实测回应质量，而非为追求跨平台强行远程化 |

### MRT2 桌面路线目前可以依据什么

**已核实的官方硬件边界。** `mrt2_small` 为 230M，官方模型文档列 Apple Silicon（包括 Air）可实时；`mrt2_base` 为 2.4B，所列 M2 Max／M3 Max／M4 Pro／M5 Max 可实时，但 M1 Pro、M2 Pro 及所列 Air 不支持 base 实时。不能仅按“名字含 Pro”筛机器；未列型号需要跑实际负载。文档没有给出我们整件作品的最低 RAM／可用磁盘指标，这两项应在模型与画面同时运行后测定。[官方硬件表与模型资源说明](https://github.com/magenta/magenta-realtime/blob/main/docs/models.md)

**系统与打包事实。** 当前官方 C++ 构建明确限于 macOS，依赖 MLX／Metal 和 Apple 框架；部署目标与独立应用的最低系统字段均为 macOS 14.0。官方代码已有独立 `.app`、UI／Metal 资源拷贝、签名与公证目标，说明可沿用现有原生应用构建路线；这不代表本作已经完成签名、公证或发行验收。[根构建文件](https://raw.githubusercontent.com/magenta/magenta-realtime/main/CMakeLists.txt)；[独立应用构建文件](https://raw.githubusercontent.com/magenta/magenta-realtime/main/examples/mrt2/standalone/CMakeLists.txt)；[应用系统版本字段](https://raw.githubusercontent.com/magenta/magenta-realtime/main/examples/mrt2/standalone/StandaloneInfo.plist.in)

Python／JAX 的 Linux／NVIDIA 路线可以用于制作端离线生成；官方当前 C++ 桌面实时包不是 Windows／Linux 通用包。若需要这些系统上的用户端实时推理，应单列移植和延迟实验，不能把一次脚本成功生成音频当作跨平台实时交付通过。

### 随包分发第三方模型时实际需要保留什么

模型卡允许的代码／权重路线已经明确：代码 Apache 2.0，权重 CC BY 4.0。Apache 的再分发条件包括附带许可证、说明修改，以及保留适用的版权／署名和存在时的 NOTICE；CC BY 4.0 允许包括商业用途的分享与改编，要求适当署名、许可证信息和修改说明，不应以额外条款或技术措施剥夺其许可范围内权利。[代码许可证 §4](https://raw.githubusercontent.com/magenta/magenta-realtime/main/LICENSE)；[CC BY 4.0 正式条款](https://creativecommons.org/licenses/by/4.0/legalcode.en)

**打包建议。** 随包建立实际用到的第三方组件清单，保留 Google DeepMind／Google LLC 的模型来源、固定修订与模型卡，给权重转换／裁剪写明修改记录。MRT2 需要 MusicCoCa、SpectroStream 和生成模型等资源，不能只带一个主权重就声称完整离线。我们可以制作包含已核实可分发资源的完整安装包，或由安装器下载固定版本并校验；下载方案应完成资源准备后再标记“离线可用”。代码还链接 MLX、TensorFlow Lite 等依赖，逐项保留实际打包版本的许可；本轮只核实主项目与模型的分发条件，没有把全部依赖审查写成已完成。

仅交付验收后的音视频输出时，不需要把 MRT2 权重一并交给用户；模型卡所述“Google 不主张输出权利”也不意味着输出自动适用模型权重的 CC BY 4.0，仍应按实际使用的采样与其他素材分别记录来源。[MRT2 官方模型卡](https://huggingface.co/google/magenta-realtime-2/blob/main/README.md)

本轮只补全交付设计，没有下载安装 MRT2 或实际制作安装包。进入制作后应由我们完成运行时封装、资源配置、目标系统启动、离线恢复与录音保存验证，再交给体验者；这些工作已在用户接受安装的范围内，不需要再次确认是否允许离开 HTML。

## 最小可证伪实验与优先级

以下数量、阈值与时间是**拟议的试作预算／淘汰条件**，不是已测结果或普遍标准。

| 优先级 | 有限样片 | 测什么，什么结果会否定它 | 应留的证据 |
|---|---|---|---|
| **P0：角色表演** | 只做“托住月牙 → 确认 → 接灯”三个镜头；总成片约 20–30 秒。每镜头最多尝试 4 个版本，先完成分镜和表演参考 | 隐去说明仍能看懂两人怎样合作；所有采用镜头中角色身份、衣领星星和月牙形状保持；接物不能凭空换手。若预算内不能做到，改分层动画或明确剪辑，不靠无限重抽 | 全部尝试、耗时／费用、逐镜头问题表、最终视频；保留失败样本，避免只展示最好的一次 |
| **P1：声音关系** | 用同一个 45 秒回声段，制作现有循环、固定响应材料、MRT2 或 Lyria 三个版本；有相应硬件／账户后再运行生成版 | 5 位首次体验者中，预设至少 4 位能在无解释下说出“另一位在听完之后才回答”；生成版若只增加新鲜音色、却破坏角色动机或句末留白，就保留固定材料。小样本只用于选择，不推导大众偏好 | 实际音频、控制事件、设备、首音及控制到可听变化的延迟、断流次数；耳机与目标设备扬声器试听记录 |
| **P2：空间记忆** | 一间柜台空间、1 盏灯、1 枚月牙；走开再返回，共 60 秒 | 用所选目标桌面／装置测渲染与读取；更重要的是回程是否自然认出自己留的位置。若物体一动就露出残影／不能独立取放，或空间绕行没有表达增益，放弃该场景生成结果 | 导出的场景与版本、视点录像、状态日志、关键视角截图；记录文件体积和实际帧时间，不只写“流畅” |
| **P2／另作：实时值班员** | 一位角色、3 轮中文对话、只登记一件虚构物品 | 测 10 组固定输入：案号、遗失时间、角色身份不得自相矛盾；打断／长沉默可恢复。若人物变成泛泛安慰助手，说明作品核心不适合该形式 | 逐字稿、录像、输入与回应延迟、错误事实；不接入主线存档写入 |
| **P3：即时世界边界** | 若已有访问资格，用 Genie 做一条 60 秒往返路线，记录同一盏灯和柜门 | 5 次往返中观察物件身份和位置是否保住、控制是否可预测；若不能，保留为概念探索。即使视觉通过，没有运行时导出／API依据，也不能判定可交付 | 原始提示与录像、往返对照帧、可用性／导出边界记录 |

当生成样片与固定材料版本都成立后，再比较制作成本和观看效果。衡量的是一次动作给人物关系增加了什么，不能只统计生成分辨率、镜头数量或曲目时长。
