# 成熟作品对照与技术路线：第二轮结论

日期：2026-09-21。依据：三位独立子代理评审、官方作品图像与演示片段、原作者技术资料，以及两项实际运行的技术探针。当前作品未因本轮研究而改版。

**我的判断：下一轮应升级资产制作与表演能力，优先试一件原生桌面的微缩小剧场。** 保留《月背拾遗司》的故事、双人关系与收藏位置；重新考虑角色、道具、镜头和声音怎样被制作、编辑与运行。现有 HTML 初版可作为故事和操作基线，后续成品不受它的结构、体积或媒介限制。

用户已明确允许下载安装和配置，只要由我们包装好。因此，浏览器、桌面程序、互动影片和配好环境的声音装置，都有被选择的空间。昂贵的模型推理可以留在制作端；普通成品接收者不必因此安装模型、Python、CUDA或编辑器。

## 1. 对照成熟作品，差距具体在哪里

团队实际查看了 Papetura、Harold Halibut 的官方场景图，以及 Assemble with Care、Gorogoa、Samorost 3 官方演示的局部连续帧；另阅读 Florence、Dordogne、NAIAD 的作者访谈或官方说明。没有声称完整实玩这些参照作品，也没有主观试听其配乐。详细证据范围分别记录在三份评审中。

| 对照对象 | 它给我们的具体启发 | 当前版本的具体差距 | 值得改变的制作基础 |
|---|---|---|---|
| [Papetura](https://petums.com/papetura/) | 少数大形体、纸张厚薄与透光形成清楚焦点 | 暖灯、金属环、纹样和月亮符号同时吸引视线；主操作还靠星号指示 | 先定动作与留白，再制作分层布景和局部光；美术需能按区域反复修改 |
| [Harold Halibut](https://press.slow-bros.com/harold_halibut/) | 人物的眼、手与同一张纸共同说明“正在办什么事” | 狐狸持标签、小狗持簿的姿态长期固定；接住、托稳、回应主要由对白表达 | 角色需要可控姿态、目光与手部接触；柜台道具需要业务与使用痕迹 |
| [Assemble with Care](https://ustwogames.co.uk/our-games/assemble-with-care/) | 部件有厚度、装配次序和持续可辨认的状态 | 翻面是换图，选中正确扣件后显示完成态；缺少同一个物件怎样被修好的过程 | 统一物件母稿、独立部件、轴心与连续动作，必要时采用真实三维资产 |
| [Gorogoa](https://www.annapurna.com/interactive/gorogoa) | 画面关系改变后，同一个东西能沿新关系继续运动 | 背景、物件弹窗和章节变化之间的联系主要由文字补足 | 场景与道具共用空间／镜头关系，变化由玩家刚做的动作引出 |
| [Florence 作者访谈](https://www.gamedeveloper.com/audio/designing-i-florence-i-to-convey-the-ineffable-feeling-of-being-in-love) | 共享物件、对话动作与角色音乐可以在前后段落改变意义 | “等待、留灯、共同安放”已有主题，但还很少让两人的做事习惯进入动作规则 | 让角色表演、玩家输入、声音回应共享时间线与状态 |

我接受评审最重要的批评：**当前气氛和包装走在动作前面。** 五章均先读四句开场，再进入近景机关，然后读收束；章节对白共 39 句，鸟尾声另 6 句。这个结构有完整性，但张弛和发现方式容易重复。封面压暗狐狸以腾出文字区、柜台近景被统一弹窗隔开，也说明构图应进一步服从人物和动作。

主代理本轮另实际操作并保存了[柜台场景](evidence/cabinet-scene.webp)、[胸针近景](evidence/brooch-near.webp)、[翻面后](evidence/brooch-back.webp)与[完成后](evidence/cabinet-after.webp)，可直接查看上述空间连续性问题。

下一轮要保留的是深青与暖灯的夜班感、两个角色的外形辨识、钟和鸟笼的小幽默、月牙的明确缺口，以及第七号柜可再次打开。参考作品的制作方法可以借鉴，具体场景、角色与素材仍需为本作重新设计。

## 2. 真正可能改变实现上限的技术

以下将已公开能力与本作尚未验证的效果分开。完整版本、模型修订、许可和来源在三份技术报告中，不因名字新就视为已可交付。

| 路线 | 新获得的能力 | 可能形成的作品 | 本轮判断 |
|---|---|---|---|
| **可编辑图层＋骨骼／网格角色**：Qwen-Image-Layered、参考图编辑、Spine或Godot二维骨骼 | 独立修改一只手或表情，让角色持续等待、伸手和接物 | 可以触碰的纸偶／布偶小剧场 | 最直接解决当前人物静止与整图不可控的问题。分层结果仍需补画、绑定，不能当成自动得到关节。[Layered 官方说明](https://github.com/QwenLM/Qwen-Image-Layered) |
| **生成网格＋人工结构整理＋原生引擎**：TRELLIS.2、UniRig、Blender、Godot | 真实厚度、背面、遮挡、灯光、角色与物件同处一个可编辑空间 | 可拿起月牙、转动木柜、返回旧位置的微缩收藏盒 | 首选制作样段方向。高精度孔位和扣件接口按规则建模，生成技术承担外观与部分初始资产。[TRELLIS.2](https://github.com/microsoft/TRELLIS.2)、[UniRig](https://github.com/VAST-AI-Research/UniRig) |
| **表演视频驱动角色／图生视频**：Wan-Animate-2、Act-Two、Veo | 更完整的身体表演、眼神和镜头变化 | 可停留、可选择次序与节奏的互动短片 | 有机会取得很大的画面与表演收益；应接受作品形式随之改变。生成时机留在制作端，运行时播放经过选择的镜头。[Wan-Animate-2](https://github.com/Wan-Video/Wan-Animate-2)、[Act-Two 双角色工作流](https://help.runwayml.com/hc/en-us/articles/41748090660499-Creating-Multi-Character-Dialogues-with-Act-Two) |
| **生成空间＋独立可操作物件**：Marble、Spark、碰撞网格／GLB | 可从不同位置查看场景，并明确保存物件状态 | 能探身进去的拾遗司，一间可重返的房间 | 空间起稿值得试。静态场景外观、碰撞、可拿物件与角色需要分别制作；Spark不能直接视作Godot内置能力。[Marble](https://www.worldlabs.ai/blog/marble-world-model)、[Spark](https://github.com/sparkjsdev/spark) |
| **可控制音符的响应式声音**：确定性分轨／MIDI、Magenta RealTime 2 | 玩家的间隔与动作改变下一句音乐 | 两个人共同演奏的月光音乐盒 | 有可能让“等待／回应”成为玩法。MRT2当前原生实时路径对Mac硬件有要求，也可只用于制作音轨。[MRT2 官方发布](https://magenta.withgoogle.com/magenta-realtime-2) |

近期模型中有几项需要特别分清：

- **Wan-Animate-2 确有公开代码和核心权重**；论文中的实时 Lite 性能不能直接当作已下载版本或浏览器能力。
- **2026-09-20 发布的 Qwen-Image-2.1** 有原生 RGBA／局部编辑能力，但采用研究许可。正式生产候选应核对具体授权；旧 Layered／Edit 版本的许可不能替它背书。[2.1 官方许可](https://github.com/QwenLM/Qwen-Image-2.1/blob/main/LICENSE)
- **实时世界模型与可保存游戏有不同交付边界。** Project Genie 当前可探索原型与录像可用于研究；本轮没有找到可让我们交付同一个离线世界、精确保留灯与柜门状态的通用运行包依据。[当前官方帮助](https://support.google.com/labs/answer/16875695)

代码公开、模型可下载、可编辑成资产、能打包交付，是四个需要分别核实的事实。研究发现足以扩大选择范围；最终采用仍由本作的小样结果决定。

## 3. 已实际运行的两个实验

**三维胸针：同一个东西可以真的翻过去。** 子代理将现有月牙轮廓做成带厚度的模型，针和扣座保留为独立节点；导出再读回 190,688-byte GLB，实际拖到侧面和背面，断网打开与导出也通过。它还没有艺术雕纹、精确机械接口、爪子或装配动画，只验证了物件连续性与可编辑结构。

打开[离线胸针观察器](experiments/brooch-3d/index.html)，或看[实验说明与截图](experiments/brooch-3d/README.md)。这个查看器使用浏览器是为了方便审样，GLB资产可以进入原生制作流程；本轮尚未把它实际导入并验证所有引擎。

**单图空间重建：空间感的收益与单幅图的边界同时可见。** 主代理实际运行 MoGe-2 小模型，把现有柜台图重建成可转动表面。800×500 输入、CPU 8线程的两次推理约 2.980／1.879 秒，不含下载、载入和后处理。小幅转头有视差；大角度下耳朵、书与前后遮挡明显拉伸，切开断层则露出缺面。

查看[空间实验](http://localhost:4173/reviews/experiments/depth-room/index.html)与[结果说明](experiments/depth-room/README.md)。它说明当前画面可以快速获得几何草稿，也说明这一具体小模型路线不能直接提供完整可行走房间。没有将该结论推广为Marble生成补全或MoGe-3的测评结果。

另有 Spark 官方轻量 SPZ 场景在本机渲染成功；复杂酒馆示例的首帧截图超时，后续物理未执行，已按未验证记录。未调用付费生成API、上传本作素材或购买算力。浏览器渲染证明可以审样，不证明最终美术或目标设备性能。

**原生修理与递灯样段已经完成第一轮接线。** [native/README.md](../native/README.md) 与 [构建记录](../native/build-notes.md) 记录了 Godot 4.7.2 Compatibility 场景：分层狐狸与小狗各自保留头、身体、上臂和前臂；同一枚胸针由可编辑三维网格组成，`R` 会连续翻到背面并打开针；三种扣件中前两种在接触处受阻，正确件合拢只触发一次声音；`L` 让一盏灯在两位值班员之间移动。Linux/Windows x86_64 便携包已导出并通过 ZIP、嵌入 PCK、PE/ELF 结构核验；真实窗口截图证明的是本机 Xvfb 与软件 OpenGL，不是目标设备性能或真人听感验收。

## 4. 我建议下一轮怎样投入

**主线候选：Godot 4＋可编辑角色／GLB道具，制作一段原生微缩剧场。** Godot的场景、动画状态、镜头、物理与音频可以组织在同一工程内；成品导出为独立程序，接收者不需要编辑器。先用明确的近景检验表现，再决定全篇采用二维纸偶、三维木偶还是混合方式。[原生制作与交付依据](tech-spatial-worlds.md#7-原生桌面候选godot-4--glb作为完整微缩剧场的交付底座)

这次的样段应有约 45–60 秒的内容，而非扩充场景数量：狐狸把月牙推到灯下，玩家连续翻看，小狗托住，错误扣件出现明确受阻，正确件落位，狐狸合针，最后两人接灯。少量姿态就可以开始，但物件身份、手部接触、声音时点和动作终点要可控制。

**竞争方案：用同一个八秒“放下簿—接灯—照标签—放回”动作，对比可编辑角色与生成表演影片。** 若影片的身体表演显著更好，且关键交接与停留可稳定控制，就让互动短片成为正式候选，不因已有解谜代码而排除它。片段生成与实时音乐所需的GPU或账户可以在制作端配置；是否让观众运行模型另行判断。

样段的检查重点：

1. 不读解释文字，能否看清谁在主动、谁在回应、月牙怎样被修好。
2. 从远景、手中、近景到归位，是否一直是同一个物件，遮挡与接触是否可信。
3. 改一只手、一次停顿或一个扣合时点，是否能局部修改而不用整段重抽。
4. 声音是否在需要等待时让出空隙，真正扣合是否只响一次；这必须试听。
5. 在实际接收设备上，能否直接启动、保存并再次打开；制作端硬件与用户端配置分开记录。

当前三个评审都支持“先完成一个有表演、物件连续性和声音关系的标准样段”。它们对表现方式有不同倾向：美术评审优先可控分层角色，交互评审优先三维物件，整体评审愿意转向互动短片或音乐小剧场。我的取舍是先让三者在同一动作上比较，保留能达到更高完成度的那条路线。
