# oncewhere

把一段真实经历，做成一件可以打开、参与、赠送和收藏的作品。

> 因为我们有过这段经历，它才会存在。

**当前阶段：理解需求与建立创作方法。** 仓库保存项目原始想法、技术研究和作品策划方法；当前仓库尚未收录已完成作品或需求验证证据，也尚未确定产品技术栈。

## 为什么做

有时，我们想送出的不只是照片或一句祝福，而是让某个人知道：那段一起经历的事情，我记得；其中只有我们理解的细节，对我很重要。

oncewhere 想探索，能否把这种心意组织成一次由接收者亲自参与的表达。寻找一件物品、翻开一封信、重新走过一条路，都可能让某段经历的意义变得可感。形式由故事决定，可以很小，也可以完全不需要 3D。

这是一项值得验证的创作主张。哪些人真的需要它、交互是否比一封信或一本相册更合适、能否持续制作和收费，目前都没有结论。

## 项目的核心，与每件作品的核心

**项目的核心**是找到一种可靠的创作方法：理解真实经历，找出对当事人重要的意义，把意义转成恰当的体验，并让作品能够被交付和留下。

**每件作品的核心**是一句只对这段关系和经历成立的表达。它回答“我为什么要把这件作品送给你”，并决定保留哪些细节、接收者做什么、最终停在哪里。

例如，备忘录中的“总在迷路的旅行”可以启发一张地图，但地图本身还不是作品核心。只有当事人确实认同某种意义——例如“最想记住的是我们一起走错的路”——寻找与绕路才有叙事理由。这只是策划示例，不是已经采集到的真实故事。

一个简单的检查：换掉姓名和照片之后，如果作品仍然对谁都一样成立，故事可能还没有真正决定形式。

## 现在做什么

先找到一个真实的赠送对象、一段明确经历和一个核心感受，完成作品简报。用谈话、纸面顺序或静态分镜验证“选的故事对不对、表达是否合适”，再决定是否值得进入交互制作。

后续的判断顺序是：真实经历 → 重要细节 → 核心表达 → 接收者的动作 → 最小载体 → 技术选择。每件作品可以有不同结果。

首件作品成立后，记录对方是否认出专属细节、是否愿意探索、是否愿意保留；再观察哪些制作能力出现了真实的复用需求。平台、模板市场和商业模式留待这些证据出现后讨论。

## 工作原则

- 经历决定形式，每件作品先有核心表达，再有功能与技术选择。
- 交互应参与叙事；简单载体已经表达充分时，就保留简单载体。
- 允许艺术化呈现，真实事件、人物原话和共同记忆以来源为准。
- 复用制作能力；故事、细节和叙事判断逐件完成。
- 收藏从一开始就考虑：正文、图像或视频等易观看备份与交付方式一起设计。

项目依据来自本仓库的原始备忘录。新增文档中的需求解释和验证方法属于工作推论与建议，不能当成用户研究结论。技术库按原版本保存，本次仓库整理没有重新核验外部工具版本。
